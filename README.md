# 📖 PageOracle: Мудрость в каждой странице

📖 **PageOracle** — интеллектуальная программная система для анализа и умного поиска информации по книгам (`.txt`) на базе Retrieval-Augmented Generation (RAG) и адаптивных графов агентов. Приложение оснащено как современным веб-интерфейсом (Flask, HTML5, CSS3, JS), так и десктопным интерфейсом (Tkinter). PageOracle выполняет синтаксическую разметку текста по главам, индексирует материалы в векторном хранилище, производит гибридный поиск (Chroma MMR/Similarity + BM25) с нейросетевым реранкингом (CrossEncoder) и формулирует точные аналитические ответы с прямыми цитатами и источниками.

## 🚀 Глава I. Работа с PageOracle

### ⚡ Быстрый запуск для Windows (без установки Python)

> [!TIP]
> **Автономный запуск в один клик:** Если вам нужно готовое приложение без установки Python, Git и настройки виртуальных сред, скачайте готовую сборку из [GitHub Releases](https://github.com/mrzolz19/pageoracle/releases).

1. **Скачайте подходящий архив**:
   - `PageOracle-windows-x64-cpu.zip` (~850 МБ) — универсальная сборка, стабильно работающая на любых ПК с Windows 10/11 x64 без видеокарты NVIDIA.
   - `PageOracle-windows-x64-cu128.zip` (~2.3 ГБ) — ускоренная сборка с аппаратной поддержкой PyTorch CUDA 12.8 для систем с дискретными видеокартами NVIDIA GeForce RTX / GTX. (не выкладывается в Releases из-за большого размера, можно скачать из Actions)
2. **Распакуйте архив**:
   Распакуйте архив в любую удобную папку (например, `C:\PageOracle` или на рабочий стол).
3. **Структура папки релиза**:
   - `PageOracle.exe` — запуск приложения.
   - `books/` — библиотека книг в формате `.txt`. Базовые книги уже включены в архив; вы можете свободно добавлять новые файлы.
   - `settings.json` — конфигурация (провайдеры, ключи API, параметры генерации), сохраняется автоматически.
4. **Запуск**:
   Запустите `PageOracle.exe` двойным кликом.

---

### 💻 Запуск из исходного кода (для разработчиков)

1. **Клонируйте репозиторий и перейдите в папку проекта**:

   ```bash
   git clone https://github.com/mrzolz19/pageoracle.git
   cd pageoracle
   ```

2. **Выберите желаемый интерфейс**:
   - Для **веб-интерфейса** (Flask Web UI):

     ```bash
     cd web_gui_pageoracle
     pip install -r requirements.txt
     python gui.py
     ```

     После старта откройте в браузере: <http://127.0.0.1:5000>
   - Для **классического десктопного интерфейса** (Tkinter Desktop GUI):

     ```bash
     cd tkinter_gui
     pip install -r requirements.txt
     python gui.py
     ```

> [!IMPORTANT]
> **Требования к среде:** Требуется **Python 3.10+**. Рекомендуется использовать виртуальное окружение (`python -m venv venv`). При установке зависимостей с CUDA PyTorch используйте параметры из `requirements.txt`.

   - **«Анализ»**: Формирует структурированный ответ с выводами, контекстом и фактологией.
   - **«Поиск цитат»**: Ищет точные словесные фрагменты текста с указанием точного источника (книга, часть, глава).

### 🖥️ Пользовательский интерфейс (GUI)

В системе реализованы два полноценных независимых графических клиента:

<p align="center">
  <img width="48%" alt="Web GUI" src="https://github.com/user-attachments/assets/c1d01884-6a17-4200-a01b-bc03c4e27e97" />
  <img width="48%" alt="Desktop Tkinter GUI" src="https://github.com/user-attachments/assets/fde12773-891a-44a1-b89e-733629d3ca72" />
</p>

- **Web GUI (Flask + HTML/CSS/JS):**
  - Централизованное управление состоянием через потокобезопасный `WebAppState` с защитой через `RLock` и `operation_lock`.
  - Полнофункциональный REST API: `/api/state`, `/api/init`, `/api/upload`, `/api/chat`, `/api/settings`, `/api/mode`.
  - Монитор логов и статусов индексации в реальном времени.
- **Desktop GUI (Tkinter):**
  - Полностью автономное нативное окно без браузера.
  - Удобная боковая панель библиотеки, история сессий и всплывающие диалоговые окна настроек (`Toplevel`).

> 3. **Сузьте контекст:** Укажите имя персонажа, ключевой эпизод, конкретную часть или главу.

### 🛠️ Диагностика и решение ошибок

| Симптом | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `ModuleNotFoundError` при старте | Не установлены пакеты | Выполните `pip install -r requirements.txt` в активном виртуальном окружении. |
| Ошибка Yandex при инициализации | Не указан `YC_FOLDER_ID` | Заполните идентификатор каталога в окне настроек и повторите попытку. |
| `mismatch dimension embedding` | Сменилась embedding-модель | Программа удалит `./chroma_intro_db` автоматически или удалите эту папку вручную для переиндексации. |
| `Контекст пуст: ретривер не нашёл` | Слишком абстрактный запрос | Переформулируйте запрос конкретнее или переключитесь на режим цитат. |
| Ошибка `HTTP 429` / Rate Limit | Превышены лимиты API | Подождите несколько секунд; в бэкенд встроен троттлинг запросов к Yandex (до 8 req/s). |

> [!WARNING]
> **Автоочистка Chroma при смене моделей:** Векторные базы строго привязаны к размерности векторов конкретной embedding-модели. При переходе с 1024-размерных векторов на 4096-размерные старый индекс удаляется и создаётся заново.

## ⚙️ Глава II. Как устроен PageOracle

### 1. Краткий обзор работы по шагам

1. **Загрузка и парсинг:** Книга `.txt` считывается и размечается регулярными выражениями на логические части (книга, часть, глава).
2. **Сегментация (Чанкинг):** Текст нарезается на чанки по 1000 символов с перекрытием 200 символов (`RecursiveCharacterTextSplitter`).
3. **Индексирование:** Чанки векторизуются и заносятся в базу данных Chroma, а также индексируются в лексическом поисковике BM25.
4. **Гибридный поиск:** При запросе параллельно срабатывают векторный поиск (семантика) и BM25 (поиск по ключевым словам).
5. **Re-ranking:** Кросс-энкодер `BAAI/bge-reranker-base` ранжирует объединённые кандидаты и отбирает ТОП-7 фрагментов с наивысшей релевантностью.
6. **Адаптивный граф агента (LangGraph):**
   - Оценивает полезность контекста (`GradeDecision`).
   - Если информации недостаточно, переписывает запрос (`RewriteDecision`) и повторяет поиск.
7. **Синтез ответа:** Выбранная LLM формулирует ответ в аналитическом стиле либо в виде строгих цитат с точной атрибуцией.

---

### 2. Обработка и индексирование документов

```text
[ .txt файл ] 
     │
     ▼
[ Регулярные выражения: поиск частей и глав ] 
     │
     ▼
[ Chunking: 1000 симв. / overlap 200 ] 
     │
     ├──────────────────────────┐
     ▼                          ▼
[ Chroma Vector DB ]     [ BM25 Retriever ]
```

- **Структурирование:** Функция `annotate_book()` находит заголовки вида `ЧАСТЬ`, `ГЛАВА`, `ЭПИЛОГ` и сохраняет их в метаданные чанка.
- **Целостность смысла:** Окно перекрытия в 200 символов гарантирует сохранение мысли автора на границах фрагментов.

---

### 3. Архитектура ядра PageOracleBackend

Класс `PageOracleBackend` выступает центральным диспетчером:

- `initialize()` — подготавливает векторное хранилище, подключает провайдера и компилирует цепочки.
- `_create_chains()` — настраивает промпты под специфику цитирования или анализа текста.
- `ask()` — передаёт диалоговое состояние в скомпилированный граф LangGraph.

> [!IMPORTANT]
> **Архитектурный принцип репозитория:** Бэкенд реализован зеркально в двух модулях: `web_gui_pageoracle/main.py` и `tkinter_gui/main.py`. Любые доработки RAG-пайплайна синхронизируются между обеими реализациями.

---

### 4. Мультипровайдерность LLM

PageOracle предоставляет унифицированный интерфейс для взаимодействия с передовыми провайдерами языковых моделей:

- **Yandex Cloud:** нативная поддержка `ChatYandexGPT` с автоматическим фолбэком на прямую маршрутизацию при отсутствии поддержки structured output.
- **OpenRouter:** доступ к моделям любого масштаба с автоматической обработкой ограничений tool calling.
- **Sber GigaChat, DeepSeek, OpenAI, Anthropic, Google:** возможность гибкого выбора модели под задачу пользователя.

---

### 5. Управление историей диалога

- **Короткая память:** Система хранит последние сообщения диалога, преобразуя их в объекты `HumanMessage` и `AIMessage` LangChain.
- **Персистентность:** История автоматически сериализуется в `chat_history.json`, сохраняя контекст между перезапусками приложения.

---

### 6. Гибридный поиск и Re-ranking

```text
           Запрос пользователя
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
[ Chroma Vector Search ]  [ BM25 Lexical Search ]
         │                     │
         └──────────┬──────────┘
                    ▼
     [ Дедупликация по MD5 хэшу ]
                    ▼
[ CrossEncoder: BAAI/bge-reranker-base ]
                    ▼
         [ ТОП-7 лучших чанков ]
```

- **Семантика + Лексика:** Векторный поиск находит суть запроса даже при несовпадении слов, а BM25 гарантирует нахождение редких имён и терминов.
- **Кросс-энкодер:** Модель совместного внимания повторно оценивает связку «вопрос — отрывок», фильтруя шум и передавая LLM идеальный контекст.

---

### 7. Адаптивный ИИ-агент на LangGraph

```text
                 [ Старт ]
                     │
                     ▼
         [ generate_query_or_respond ]
                     │
         ┌───────────┴───────────┐
         ▼                       ▼
    (Прямой ответ)          (retrieve)
         │                       │
         │                       ▼
         │            [ _route_after_retrieve ]
         │             (Оценка релевантности)
         │                       │
         │             ┌─────────┴─────────┐
         │             ▼                   ▼
         │        [ Релевантно ]     [ Не релевантно ]
         │             │                   │
         │             │                   ▼
         │             │          [ rewrite_question ]
         │             │             (до 5 попыток)
         │             │                   │
         │             │                   └───────┐
         │             ▼                           │
         │     [ Генерировать ответ ]              │
         │     (analysis / quote)                  │
         │             │                           │
         └─────────────┼───────────────────────────┘
                       ▼
                    [ Конец ]
```

Граф агента адаптируется под сложность запроса: если первичный поиск вернул нерелевантные фрагменты, узел `rewrite_question` переформулирует поисковую фразу и запускает повторный цикл поиска, минимизируя галлюцинации и пропуски фактов.
